# CLAUDE.md

> **⚠️ THIS REPO IS PUBLIC.** Everything you write here is world-readable:
> code comments, commit messages, **PR titles and descriptions**, PR/issue
> comments, `readme.txt`, and release notes alike. Never name another Oyster
> repo, a PR/issue number in one, or the internal classes, tables, endpoints
> or infrastructure of anything outside this repo. Describe *behavior* of the
> backend Oyster talks to, never its internals. Read **Public repo hygiene**
> in [AGENTS.md](AGENTS.md) before writing any of the above. This rule has
> been broken before in a sibling repo, via a PR description.
>
> A PR description is a **published document, not a message to a colleague**.
> No one addressed directly, no narration of what you tried, no live status, no
> "merge this first". Status and coordination go to the team channel; the PR
> gets the change. See **A PR description is a document, not a message**.
>
> This plugin transmits a customer's **phone number and name** to a third
> party. Read **Security invariants** before touching anything on that path.

See [AGENTS.md](AGENTS.md) for the full guide (architecture, conventions,
security invariants, git workflow, release process, testing). Keeping the
guide in one file. Read that one; this file is just a pointer so it isn't
duplicated and doesn't drift.
